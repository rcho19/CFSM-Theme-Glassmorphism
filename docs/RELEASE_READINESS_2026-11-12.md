## 合成数据浏览器与请求检查

使用回环地址、合成节点和临时计数服务。临时服务补齐 WS close 帧响应，避免把等待关闭握手的 TCP 连接错误计为应用保留连接；没有修改生产代码或依赖。结果不能替代真实 Cloudflare 鉴权、验证码或配置保存验收。

- 首页初始化：config、servers 各一次，WS 显式 scope=all，单节点列表 ids 数量为 1；停留期间计数没有周期增长。
- 进入详情：新增一次 server、一次 history/all；订阅范围变为当前合成节点，原首页连接收到 close 帧并关闭，稳定后只留一条连接。
- 手动切换 30 分钟：history/all 增加一次；返回首页不重取 config/servers，详情连接关闭并恢复首页订阅。页面过渡期间连接握手可短暂重叠，不把最终一条连接表述为全程绝无重叠。
- 完成所有临时标签清理后，服务计数为 13 次打开、13 次关闭、0 活跃连接。两套浏览器页面各初始化一次，最终 config/servers 各两次，history/all 共两次。
- 三网方向键查看可显示时间桶、延迟与丢包；Escape 可退出。色块模式为三条线路、每条 20 桶；没有把缺失值补成 0。
- 四种卡片密度分别在浅色、深色下检查，共八组：三网均为三条，桌面没有横向溢出；仅临时保存本地设置，完成后清除到 0 项本地覆盖。
- 最终菜单过渡恢复：同一节点切换菜单时可见 enter-active 和透明度变化，只有一张卡片，不跨列跳动。
- 真实后台可见性事件未在当前 Chrome 调试环境中可靠观测到，不能列为实际通过。单元测试覆盖关闭、恢复、最多十次退避及无 REST 回退，仍需在常规浏览器、不受调试影响的环境复验一次隐藏和恢复。

### 实际视口复核与小屏问题

发现 Chrome 调试控制接受尺寸参数后，实际 innerWidth 仍为 1443，故废弃这些“移动端”测量，改用独立预览浏览器核对实际 innerWidth。此次复验取代之前只按请求尺寸记录的 Chrome 移动结论。

| 请求宽度 | 实际 innerWidth | clientWidth / scrollWidth | 卡片与过渡 |
|---|---|---|---|
| 320 | 320 | 310 / 310 | 一张卡片、原格进场 |
| 375 | 375 | 365 / 365 | 一张卡片、原格进场 |
| 768 | 768 | 758 / 758 | 一张卡片；补采捕获 opacity=0 及 enter-active |
| 1440 | 1440 | 1430 / 1430 | 一张卡片、原格进场 |

clientWidth 与 innerWidth 的差值来自当时的滚动条，不是横向溢出。375px 最终截图时滚动条状态变化，clientWidth/scrollWidth 均为 375，仍无溢出。

**P2 可读性问题：375px 下部分首页总览长数值被省略显示，节点卡片指标仍完整。** 没有横向滚动不代表所有数字都可读。应对照上游设计复核该处排版；本轮只记录，不修改业务代码。物理触屏、Safari/Firefox 与长时间压力尚未实测，不能宣称全浏览器/真机兼容。

本地日志、合成数据截图和计数证据存于被忽略的 outputs/release-*；不包含生产凭据。独立浏览器实际视口截图为 outputs/release-readiness-mobile.png。所有临时视口恢复默认，临时标签、设置和服务均在验收结束时清理。
