# 实时负载曲线排查

## 范围与验收

目标是解释并修正“负载实时有数值、有坐标轴、没有曲线”的可见问题。保留真实断点、原始采样和现有 ECharts 渲染器，不增加轮询、不调整 Worker/Agent 或站点权限，不部署或推送。先验证缓冲及绘图配置，再用单节点合成数据验证稀疏和连续采样，最后串行运行质量门。

验收：稀疏真实样本可见，缺口仍断开；连续样本仍画线；秒级历史可以垫底且与毫秒推送去重；缺失值不变为零；缓冲仍有十分钟/600点上限。回滚仅需还原本轮 domain 修改和对应测试，重建主题，不涉及数据库。

## 证据与结论

- 线上实时图可见坐标轴、指标标题和时间轴，但未见有效线段。后续观察标题数值变化，不能把它写成“完全没有数据”，也不能据此证明持续收到 WebSocket 推送。
- 本地每秒合成推送可正常绘线，说明渲染器并非普遍失效。
- `buildLiveChartRows` 在相邻点超过一分钟时插入 null；`line` 同时设置 `showSymbol:false`。当每个点都被缺口隔开时，无可连线、无可见点，真实数据在画面上消失。保留断点并只为孤立点设置圆形标记，连续段仍隐藏点。这是 CFSM 稀疏数据的必要可视化差异，不伪造连接。
- `seedLivePoints` 原先直接用历史时间戳与毫秒窗口比较；秒级历史会被当作过期丢弃。统一秒/毫秒再裁剪和去重，与普通历史图及推送入口语义一致。该缺陷由合成行为测试确认，尚未取得足够证据认定线上历史恰好触发此问题。
- 两个回归用例均先在修复前失败，再于修复后通过。未提取或使用生产凭据进行测试，未将生产数据写入测试。

## 后续只读核实：上报条件

在现有已登录的官方管理页，读取到 Agent WSS 上报关闭；节点编辑窗口中的当前值为仅 HTTP POST、上报间隔 120 秒、采集间隔 0。读取后取消退出编辑，并返回原设置页，再次确认 WSS 开关未改变。没有点击保存，没有变更节点、站点权限或上报配置。

因此当前不能按每几秒一条的 WSS 实时链路预期页面行为：HTTP 上报的稀疏点会超过主题的一分钟断点阈值，旧版隐藏孤立点后就完全不可见。公开参考源码 `src/utils/agentConfig.js` 中 `buildAgentConfig` 在全局 WSS 关闭时下发 HTTP 模式；`src/handlers/update.js` 的 WSS 接口也会拒绝关闭状态。这与管理页当前参数一致，但公开 main 源码不是线上部署文件的逐字证明。

本轮只修正主题对已有真实数据的显示，没有替用户开启 WSS。如果要高频实时曲线，需要用户另外授权启用 Agent WSS，并把该节点从仅 HTTP 改为自动模式，再核对 Agent 的 WSS 间隔及后端预算。HTTP 模式保持不变时，应接受稀疏点而不是期待连续高频折线。两处本地修复仍须提交构建、安装后才能在线上生效；不能把本地合成测试视为已验收生产 WSS。
